זהו **מקור התכנון המחייב של Taamify** (בענף מסמכים מבודד). Dvir OS מציג את מצב המחקר, המשאבים, המדדים, הסקירות וההרשאות; הוא אינו מחליף את פייפלייני Python, מערכת התורים או FastAPI של Taamify. המטרה היא להפעיל מחקר אקדמי מדיד ומקביל לו שיפור מוצר מבוקר.

## למה יש ענף מסמכים

- המחשב המקומי מחזיק, על פי דיווח מיום 22.10, את `v3-tradition-finding` **53 קומיטים לפני GitHub**. הענף המרוחק כולל מחקר קודם; הוא אינו משקף את תיקוני 02.10.
- **אין לדחוף force, לא לדרוס את המקומי ולא למזג תוכנית זו למערכת פרודקשן עד בדיקה.** הענף החדש `docs/taamify-research-os-handoff-20261022` מכיל קבצים תחת `docs/research-os/` ו־`research_os/` בלבד כדי לצמצם התנגשויות.
- תחילה קרא `AGENT_HANDOFF.md` ו־`BRANCH_SYNC.md`; משם המשך לפי סדר הפעולות. זהו מסמך handoff אמיתי, לא רק רעיונות למחקר.

## ממצאים קיימים — **לא לייחס אותם למחקר החדש**

`PLAN_STAGE_A.md` מתעד ששלב א׳ נסגר עם 87.9% דיוק טעם, AUC 0.995, 89.4% גילוי טעויות בתקציב 2% התרעות שווא, 8 פרשות מוחזקות ו־API חי, **על קורא בן13 בלבד**. שיעורי התרעות שווא בערוצי דקדוק נפרדים נותרו 5.6%–8.1% אחרי שיפור חלונות חיתוך. קובצי GitHub המרוחקים ישנים יותר; המסמכים הללו אינם אימות של המצב המקומי. לפני כל ניסוי יש לשחזר metrics מול commit, dataset manifest, checkpoint ושרת מתאים.

## שאלת העל

האם ניתן לבנות מורה דיגיטלי שמזהה **את הטעם שבוצע בפועל** ולא זהות קורא/טקסט צפוי/מיקרופון, ולהוכיח הכללה לדובר חדש בנוסח ספרדי־ירושלמי באמצעות מדידה בלתי תלויה?

המיזם מאפשר שתי תרומות נפרדות: 
1. **מחקר אקדמי:** ייצוגים אקוסטיים ומלודיים והכללה בין קוראים, בקרות מול טקסט ו־voice conversion.
2. **מוצר:** מנוע אימות שמסביר שגיאות ממשיות, מווסת חוסר ודאות, ושומר שיעור התרעות שווא נמוך דרך API חי.

### אזהרה לסוכן
חבילת Research OS שנוצרה קודם בשיחה כ־ZIP אינה מותקנת אוטומטית ב־repo המקומי. קוד `research_os/plan.py` הכלול בענף זה הוא CLI תכנון ואינו מפעיל אימון. *אין להכריז שהמודלים P00–P12 אומנו או שה־Dashboard מחובר לשרת.* יש לשחזר את רכיבי מחקר OS בהדרגה בתוך ה־checkout המקומי העדכני ורק לאחר אימות ההיסטוריה המקומית.
